# 0.5.0 Skill 与 MCP 批处理验证

## 边界

Skill 是可发现、按需加载的日常操作指导；程序执行放在 MCP 批处理。识图、原图核验、全部叠加图/放大图检查仍由模型完成，不能由程序替代。日常 skill 不包含安装或全局维护任务。

## 一致性

通过真实 MCP stdio 创建两个相同的独立合成任务，每任务两页面板、4 条曲线、12 点。单步路径分别提交/精修/复核，再导出；批处理路径每面板 submit_and_refine，读取叠加图和全部放大图的 image 返回值后一次 review_and_export。两条路径都实际运行本机 GetData 2.20；独立读取保存后的 Excel XML，标题/指标/曲线含义、点数、X/Y 全部一致（数值容差 1e-12）。合成任务为程序几何回归，图像返回类型不代表模型实际识图验收，也不是模型视觉能力测评。

| 固定状态变更阶段 | 单步 | 批处理 |
|---|---:|---:|
| 两面板提交及精修 | 4 调用 | 2 调用 |
| 两面板复核及导出 | 3 调用 | 1 调用 |
| 合计 | 7 调用 | 3 调用 |

排除两边相同的准备、读图、看图和查询操作；调用次数来自 MCP 测试实际记录。减少 4 次固定调度（约 57%），不代表测量了实际模型推理轮数、总 token 或总时延。同一轮模型本来也可能发出多个工具调用。

## 失败保护

- 提交/精修阶段中途失败，旧 job.json、接受状态和原叠加图不变；新派生文件仅在独立 revision 目录留诊断。
- 任一个复核无效、缺逐点说明、旧 revision、重复/未知面板、未覆盖待复核面板或空覆盖说明，整批复核均不提交。
- 接受后源像素变化会阻止导出；重提/重精修生成新 revision 并撤销接受。
- GetData 导出失败时保留有效复核，last_batch 标明 export_failed，原成功结果保留；修复导出问题后直接重试 export_workbook。
- 批处理按单 job 串行约定执行，不提供数据库级事务或跨进程任务锁。

## Harness 兼容性

对照官方 SkillRegistration 类型检查注册字段，Node 测试验证 optional ctx.inject(['skills']) 在服务缺失/延迟时不阻断 MCP，服务出现后注册可供模型与用户调用的 skill，目录资源与 reference 均可解析。标准 SKILL.md 已通过 skill-creator 的 quick_validate。没有在真实 Harness 桌面完整安装并运行模型；实际 skill 发现/加载和图片接收仍需接收者环境验收。

CI 在 Windows/Linux 运行契约、单步回归和批处理便携检查；没有 GetData 时只验证明确拒绝与复核状态，不冒充桌面导出成功。本机 --getdata-exe 模式额外覆盖实际软件。
